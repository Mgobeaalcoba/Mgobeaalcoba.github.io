# Studio: site-wide coverage and themes

The second rebrand pass completes the internal MGA page families and applies the owner's approved softer palettes. See [ADR 0005](../decisions/0005-studio-sitewide-themes.md) and the original [benchmark](reports/Rebranding%20de%20consultor%C3%ADa%20MGA.md).

| Role | Light | Dark |
| --- | --- | --- |
| Page | `#E9ECE7` | `#11161D` |

| Raised surface | `#DFE4DC` | `#24303C` |

| Secondary text | `#53615D` | `#A4B1B4` |
| Primary action | `#3D59C7` | `#7E96F2` |
| On primary | `#F4F5F1` | `#11161D` |
| Cyan text | `#296680` | `#88B2C4` |
| Lime accent | `#9CBF4B` | `#AACB62` |
| Lime text | `#486626` | `#AACB62` |

Blue is the default action color. Lime fills are limited to decorative details; light-mode emphasis text uses blue. Status colors and fifteen chart categories also have theme-specific roles. Brand assets generated by `scripts/generate-studio-assets.mjs` use the dark palette for fixed icon/social-cover compositions.

Text accents have stronger light-mode ink variants so labels also work on tinted and raised surfaces. Blue text uses `#3652BB`; primary buttons retain `#3D59C7`. Neutral closing sections explicitly use normal text, replacing the earlier inverted text/background pair together.

## Implementation

- `src/app/studio-theme.css`: canonical palette, legacy aliases, common controls and chart roles.
- `src/app/studio.css`: original Studio shell and homepage layout.
- `src/app/studio-pages.css`: completed page families, surfaces, reading columns and responsive rules.
- `src/app/studio-assistant.css`: the complete first-party chat interface, identity form, message content and composer; the existing assistant hook and lead/message endpoints are unchanged.
- `src/app/studio-mobile.css` and `MobileNavigation`: compact header, bottom navigation, Explore sheet and safe-area/overlay layout.
- `src/app/studio-projects.css` and `ProjectDemos`: local interactive illustrations for El Portugués, Racing and Unicorn, with their real site/case links and visible illustration/project-status labels.
- `StudioPageIntro`: shared heading, description, actions and optional aside.
- `useStudioChartTheme`, `studioChartTheme` and `StudioCharts`: canvas subscription, resolved colors and report-chart adapters. SVGs use CSS tokens directly. INDEC and PyPI reuse the same palette while retaining their existing data logic.
- Root prepaint script: reads stored/system appearance before React hydration. `ThemeProvider` persists subsequent changes. The server and initial client render keep the same structural tree.

Paths above are relative to `apps/web/`. Add new color roles to the theme stylesheet instead of introducing light/dark hex literals in page components. Fixed client-media colors are an intentional content exception.

The archive cards use independent bordered surfaces with 32px internal spacing on desktop and 24px on mobile. AgentHub's illustrative preview shows a compact question/context/answer flow; it is not a live calculation or an imitation dashboard. Founder photos keep their original colors in both the homepage thumbnail and portfolio.

Mobile uses bottom navigation rather than a hamburger menu. Home, Services, Work and Contact are direct actions; Explore opens a compact sheet. Shared layout reserves bar/safe-area space. The assistant is reached from Explore on mobile; floating contact/assistant triggers are hidden to keep content clear. [ADR 0007](../decisions/0007-mobile-navigation-project-demos.md) records the decision.

Neil and El Portugués applications, verification documents and the embedded game are separate assets. Their own brand/media presentation is preserved. The surrounding MGA pages are themed. Racing is now a public Next.js case; the former proposal path redirects directly to it. See [ADR 0006](../decisions/0006-public-racing-case.md).

## Verification approach

Use the repository's full `npm run check` with the existing Webpack fallback if the local environment blocks Turbopack's internal port. Review representative page families in both modes; test desktop, mobile and 320px minimum width. Verify theme changes without losing filters, resource category/hash navigation, article search, AgentHub disclosures, menu keyboard behavior and contact fields without sending messages or purchasing.

The session-specific checks, environment limitations and publication status are recorded in [STATE](../STATE.md). Build-refreshed data snapshots are restored when unrelated to the design change. Generated Next.js output is never staged.

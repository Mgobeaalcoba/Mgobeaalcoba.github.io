19:Tf5d,<p>Polars promete ser 10-100x más rápido que Pandas. Hice benchmarks reales con datasets del tamaño que procesamos en producción. Los resultados son interesantes.</p>
<h2>Setup del benchmark</h2>
<p>Dataset: 50 millones de filas, 12 columnas (similar a nuestra tabla de eventos).</p>
<pre><code class="language-python">import pandas as pd
import polars as pl
import time

# Generamos datos de prueba
n_rows = 50_000_000
df_pandas = pd.DataFrame({
    "user_id": np.random.randint(1, 1_000_000, n_rows),
    "event_type": np.random.choice(["view", "click", "purchase"], n_rows),
    "gmv": np.random.exponential(500, n_rows),
    "created_at": pd.date_range("2025-01-01", periods=n_rows, freq="s"),
    "country": np.random.choice(["AR", "BR", "MX", "CO", "CL"], n_rows),
})

df_polars = pl.from_pandas(df_pandas)
</code></pre>
<h2>Benchmark 1: GroupBy + Aggregation</h2>
<pre><code class="language-python"># Pandas
start = time.time()
result_pandas = df_pandas.groupby(["country", "event_type"]).agg(
    total_gmv=("gmv", "sum"),
    count=("user_id", "count"),
    unique_users=("user_id", "nunique")
).reset_index()
pandas_time = time.time() - start

# Polars
start = time.time()
result_polars = df_polars.group_by(["country", "event_type"]).agg([
    pl.col("gmv").sum().alias("total_gmv"),
    pl.col("user_id").count().alias("count"),
    pl.col("user_id").n_unique().alias("unique_users"),
])
polars_time = time.time() - start

print(f"Pandas: {pandas_time:.2f}s")   # 18.4s
print(f"Polars: {polars_time:.2f}s")   # 1.8s
print(f"Speedup: {pandas_time/polars_time:.1f}x")  # 10.2x
</code></pre>
<h2>Benchmark 2: Filtros + Joins</h2>
<pre><code class="language-python"># Pandas
start = time.time()
filtered = df_pandas[

# Polars - lazy evaluation
start = time.time()
result = (
    df_polars.lazy()

    )
    .join(sellers_polars.lazy(), on="user_id", how="left")

<p>Polars usa memoria más eficientemente gracias a Arrow columnar format.</p>
<h2>Cuándo Pandas sigue siendo mejor</h2>
<ol>
<li><strong>Ecosistema</strong>: scikit-learn, matplotlib, seaborn — todos hablan Pandas nativamente</li>
<li><strong>Operaciones string complejas</strong>: Pandas tiene operaciones de string más ricas</li>
<li><strong>Datos pequeños</strong> (&#x3C; 1M filas): la diferencia no importa</li>
<li><strong>Interoperabilidad</strong>: más fácil de integrar con código existente</li>
</ol>
<h2>Cuándo usar Polars</h2>
<ol>
<li>Datasets > 5M filas donde la velocidad importa</li>
<li>Transformaciones que se pueden expresar con lazy evaluation</li>
<li>Proyectos nuevos donde podés elegir libremente</li>
<li>Cuando la memoria es un constraint</li>
</ol>
<h2>Conclusión</h2>
<p>Polars es genuinamente más rápido. El speedup de 10x en groupby/aggregation es real y reproducible. Si empezás un proyecto nuevo hoy y vas a procesar datos grandes, Polars es la elección correcta.</p>
<p>Para proyectos existentes: migrar no es trivial, la API es diferente. Solo vale la pena si tenés problemas reales de performance.</p>
